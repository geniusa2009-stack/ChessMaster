# ChessMaster Campaign Architecture

Generated summary of the R7 connected educational system.

## Source of truth
- `src/features/campaign/lib/catalog.ts` — worlds, chapters, levels (stable ids CHxx-Lyyy), video registry inputs, boss inputs.
- `videos.ts` — generated video lessons + bosses.
- `resolve.ts` — pure resolver (level → real puzzle/opening ids, playable vs planned).
- `eligibility.server.ts` — server-only wrapper feeding the verified corpus.
- `graph.ts` / `progress.ts` / `validate.ts` — acyclic prereqs, server-authoritative state, integrity.
- `/api/campaign` — auth-gated, own-data state. Reports generated by `scripts/audit-campaign.ts`.

## Entity relationships
Level —teaches→ Skill; Level —achieves→ Objective; Level —requires→ Prerequisite Level; Level —uses→ Puzzle/Opening; Level —includes→ VideoLesson; VideoLesson —explains→ Objective; Assessment —evaluates→ Objective; TrainingEvidence —updates→ SkillProgress; SkillProgress —unlocks→ Next Level.

## Video attachment contract
A video attaches later by setting its `asset` + advancing `state` to `published` for the existing stable video id — no campaign restructuring, no puzzle-id changes. Only approved videos with a real asset may publish; all are PLANNED in R7.
