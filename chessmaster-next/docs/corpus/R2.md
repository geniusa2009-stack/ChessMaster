mismatches, full integrity of five SQLite databases, DuckDB accessibility and all
261 committed R1 shards. Earlier 805-file R1 and 134-file R2 acquisitions remain

Acquisition preserves completed targets, uses per-file claims and manifest locks,
checks saved partial-prefix digests and final HTTP validators, and validates

There were no partial byte-range downloads at the continuation baseline. New

## Relations and opening graph

`relations_r2.py` uses one sequential R1 scan and indexed active R2 targets.
Exact position comparisons retain side to move and legal castling/en-passant
state. Exact duplicate edges additionally require full FEN and canonical line.
All source records remain separate. Exact matches do not authorize educational
merges. Relation run identities include the active target set and R1 high-water
mark; historical runs remain available.

Similarity is an incomplete candidate generator: material/turn and a 16-bit
SimHash prefix, with at most 64 prior candidates per record and Hamming distance
at most eight. It does not assert educational equivalence. Alternative solution
relations require replayed proof certificates for the same modeled mate horizon.

`graph_r2.py` retains named source paths and first-20-ply prefixes from standard
games. Prefixes are not named variations. Transpositions link distinct paths
without merging names; graph and game consolidation remain incomplete.

## Verification evidence

Existing finite Stockfish results are preserved with binary/configuration
identities. They do not establish objective proofs or uniqueness.

`objectives_r2.py` and `mate_proof_r2.py` construct and independently replay
exhaustive orthodox mate certificates with all defender replies covered. Budget
exhaustion is incomplete evidence. Uniqueness means unique first move within the
explicit modeled horizon, not uniqueness of every continuation. Proven alternate
roots remain separate evidence.

`popeye_r2.py` handles applicable orthodox directmates #1–#5. Native keys are
checked independently with the exhaustive verifier. A proof establishes a forced
mate within the modeled horizon; it does not compare a missing published solution
or establish exact-length composition soundness. Help/self/fairy/retro genres
remain explicitly unsupported by this adapter.

`endgames_r2.py` probes only installed Syzygy material and dependencies. It records
missing filenames and hashes the installed table files. A fresh-FEN unconditional
win/draw value can verify that study objective, but does not verify the published
solution or uniqueness. Ten three-man files do not imply general tablebase coverage.

`query_r2.py --with-evidence` returns summaries from separate verification stages;
it does not overwrite the source normalization status.

A maintenance lock serializes graph construction against R2 import workers. Optional
record/time limits are for measured benchmark runs. A file selector selects a
whole snapshot, not a sample. Keep headroom for writers, WAL and the host.

Private evidence includes per-file receipts, import history, cross-source run

The two large Lichess archives alone require 53,481,991,726 compressed bytes,
before working output. Saved plans also contain unknown sizes and failed URLs.
`storage_r2.py` reports a known-byte lower bound and measured prefix projections;
complete game/evaluation/index/solver expansion remains unknown. An exact full
working-space total cannot honestly be inferred from current inputs.

All content remains `RIGHTS_REVIEW_PENDING`. Publish scripts, tests and safe
aggregate metadata only. Raw archives, records, private proofs, databases,
credentials and HTTP headers stay outside Git. Production application, Supabase,
migrations, content activation and main are untouched.

Full integrity audits record file size, modification time, filesystem identity, WAL state and SQLite
version. `--reuse-integrity /path/to/prior-full-audit.json` reuses a passed check
only when those fingerprints still match; changed databases receive a new full
check. Checkpoint writers first. Loopback curl-resumption tests are opt-in with
`CHESSMASTER_TEST_LOCAL_HTTP=1`; private format tests use
`CHESSMASTER_TEST_PRIVATE_FIXTURES=1`. Skipped tests are reported separately.

For read-only audit runs, `--mmap-bytes 2147483648` optionally uses file-backed
reads up to the SQLite build limit. The independent full task-index check took
76.5 seconds on the measured snapshot; this is not a latency guarantee. See
[SQLite memory-mapped I/O](https://sqlite.org/mmap.html). Ordinary buffered reads
remain the default.

Resumed HTTP downloads must establish the complete object length from the final
Content-Range when HEAD omits it. A response that ends before the object end stays
incomplete; generated loopback fixtures cover both cases.
